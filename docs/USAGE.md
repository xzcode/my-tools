# 日常使用

## 快速上手

打开 Toolbox EX 后，左侧按数据、文本、编码、日期和开发辅助分类。点击工具，粘贴输入、设置选项，再点击右下角处理按钮。`Cmd/Ctrl+Enter` 等同于开始处理；`Cmd/Ctrl+K` 搜索工具；`Cmd/Ctrl+,` 打开偏好设置。

桌面应用运行期间，默认 `CmdOrCtrl+Shift+Space` 呼出独立快捷窗口。输入工具名称后用方向键选择、回车在主工作台打开。Esc 隐藏快捷窗口。快捷键可在偏好设置中修改或留空禁用；被其他软件占用时会显示原因。

## 常见任务

| 任务 | 操作 |
| --- | --- |
| JSON 格式化 | 粘贴 JSON，选择缩进，点击格式化；输出可切换树形视图 |
| JSON 路径提取 | 在“提取路径”填写 `$.settings.theme`、`$["a.b"]` 或 `/items/0`，选择提取路径再处理 |
| 多行转带引号列表 | 字符串拼接 → 包裹字符“双引号” → 分隔符 `,`，可勾选去重/去空行 |
| SQL IN | 每行一个值，填写字段名、方言和值类型，生成后检查再用于自己的 SQL |
| 中文 Base64 | 文本输入默认 UTF-8；编码后可交换输入/结果，再选择解码验证 |
| AES 加密/解密 | 设置自己的加密口令（至少 8 字符，建议使用强密码），粘贴明文点击“加密”，把生成的完整 JSON 密文保存下来；解密时输入该 JSON、填相同口令后点击“解密” |
| 强密码生成器 | 设置 12–128 字符与 1–50 条，选择大写、小写、数字、符号及易混淆字符过滤，点击“生成密码”即可复制结果 |
| 文件 Base64 | “文件 → Base64”选择原始二进制文件；“输入 Base64 → 文件”将输入的编码保存为二进制 |
| 时间戳 | 明确选择秒或毫秒可避免自动识别歧义；日期输入使用含时区的 ISO 格式 |
| JSON/YAML/CSV | 选择输入/输出格式；CSV 对象表格适合扁平对象数组，CSV 默认保留值为字符串 |
| 两段内容对比 | 文本或 JSON 对比工具中分别填入原始内容和修改后内容，再处理 |
| 正则测试 | 表达式不写两侧 `/`，标志单独填写；复杂表达式超过 2 秒自动终止 |
| cURL 请求整理 | 粘贴常见 POSIX cURL 命令，解析 Header、查询参数、Body；不会发送请求 |

“填入示例”会覆盖当前工具的输入与配置并执行示例。AES 是例外：只填入演示明文，不自动设置真实加密口令或执行加密。需要保留当前输入时先复制或导出。

## 文件与批量处理

文本导入要求 UTF-8，非法编码会提示错误。二进制文件使用 Base64 专用文件按钮。不设普通文件的产品容量上限。

支持批处理的工具右下方有“批量处理”。选择所需文件，设置当前动作与选项，点击开始。每个文件独立显示成功或错误；可停止当前批次。成功结果可批量导出，不设固定数量或总量配额。

桌面批量导出会在选择的目录内建立新的结果文件夹，不覆盖原文件。浏览器预览导出为 ZIP。单文件导出使用系统保存对话框，选择已有目标时遵循系统覆盖确认。

## 结果与草稿

修改输入或选项后，原结果标记为“待重新处理”；请再次执行，避免复制过期结果。取消/失败不会把不完整结果当成成功。

**AES 安全提示：**使用 AES-256-GCM 和 PBKDF2-HMAC-SHA256（600,000 次），每次加密随机生成 16 字节盐与 12 字节 IV，生成的 JSON 包含解密所需的元数据及认证密文。口令不包含在 JSON 中，必须另外妥善保管。修改或丢失口令后无法恢复原文；错误口令及修改过的密文不会输出未经认证的结果。本工具格式不直接兼容 AES-CBC、ECB、OpenSSL 或 CryptoJS 的默认输出。密码生成器使用 Web Crypto 安全随机源，默认生成 24 字符密码，并保证每个选中的类别至少出现一个字符。

工具之间切换会保留各自独立标签。全部工具参数、输入、输出、文件与历史自动保存在本机，包括 AES Key、前缀、IV 与 AAD。历史恢复在新标签中完整还原实际保存的内容。“清空”仅清除当前标签的处理内容与相关密钥；重要历史由用户自行删除，也可以清除全部工作台。

## 个性化

收藏星标可把常用工具放到导航顶部。最近使用记录的是工具名称，不是处理内容。偏好设置可以清空最近记录、选择深色、纯黑、灰色、浅色、柔和白色或跟随系统，以及调整桌面关闭行为。

默认构建关闭在线更新。安装新版本可手动下载新安装包；只有配置并编译了签名更新的版本才提供在线检查按钮。发布状态见 `RELEASING.md` 和 `HANDOFF.md`。


## AES 高级模式（0.3.0）

在 **AES 加解密 → AES 工作模式** 中选择“高级模式 · 原始 Key / IV”。高级模式与简单模式的密文结构不同，使用的是精确长度的原始 AES 密钥（不执行 PBKDF2），不能把普通短密码随意当作原始 Key。

参数说明：

| 参数 | 选项 | 说明 |
| --- | --- | --- |
| 加密模式 | GCM / CBC | 新系统推荐 GCM；CBC 仅用于旧系统兼容，不提供认证 |
| 密钥长度 | AES-128 / 192 / 256 | Key 必须分别为 16 / 24 / 32 字节 |
| Key 编码 | UTF-8 / Hex / Base64 | 按选定编码解码成真正的 Key 字节，不做补零或截断 |
| IV 编码 | UTF-8 / Hex / Base64 | GCM 恰好 12 字节，CBC 恰好 16 字节 |
| 明文编码 | UTF-8 / Hex / Base64 | 加密时表示输入明文的编码；解密时表示输出明文的编码 |
| 密文编码 | Base64 / Hex | 加密结果的编码及解密密文输入的编码 |
| CBC Padding | PKCS7 / NoPadding | Java AES/CBC/PKCS5Padding 对应 PKCS7；NoPadding 要求明文是 16 字节整数倍 |
| GCM Tag | 128/120/112/104/96 bit | 默认 128；Tag 可附在密文末尾或分离为 JSON 的 tag 字段 |
| AAD | UTF-8 / Hex / Base64 | 可选的关联认证数据，不加密，解密时必须相同 |

**Java AES/CBC/PKCS5Padding 示例**：设置 CBC、AES-128、Key 编码 UTF-8（例如准确 16 个 ASCII 字符）、IV 编码 UTF-8（准确 16 字符）、Padding=PKCS7、明文 UTF-8、密文 Base64。这样产生的密文字节可与 Java AES/CBC/PKCS5Padding 实现互通，前提是所有参数完全一致。

**Java AES/GCM/NoPadding**：设置 GCM、指定 Key/IV、Tag 128 bit 和“附在密文末尾”，对应 Java 常见的 Cipher.doFinal() 输出（密文 + Tag）。Node.js 的分离 Tag 用“独立字段 JSON”，它包含 ciphertext 与 tag 两个字段，均按所选的 Base64/Hex 表示；解密时选择相同的分离 Tag 形式并输入该 JSON。

**IV 安全**：高级模式不会悄悄固定或自动重用 IV。点击“生成随机 IV”会使用系统安全随机数并设置 Hex 编码；每次 GCM 加密都要重新生成，随后将该次 IV 与密文一起保管。IV 不是秘密，但丢失会导致无法解密。手动填入固定 IV 是为旧系统联调提供的兼容能力，不意味着可以安全重复使用固定 IV。

**保密边界**：Key、口令、明文和密文只在当前运行会话内存中；关闭应用后不恢复。复制或导出时，相关内容会进入操作系统剪贴板或用户选择的文件。AES-CBC 未认证，错误 Key 可能产生看似可读但实际不正确的文本；需要校验安全性时请用 GCM。


## Java AES/ECB/PKCS5Padding 旧系统兼容（0.4.0）

在 AES 工具栏点 **Java ECB/PKCS5**，自动设为高级模式、ECB、AES-256、Key UTF-8、PKCS7、明文 UTF-8、密文 Base64。**ECB 没有 IV**，IV 编码/输入框会自动隐藏，之前输入的 IV 也不会被使用。

与 Java SecretKeySpec(raw, "AES") / Cipher.getInstance("AES/ECB/PKCS5Padding") 对接时，必须确保 Key 采用 Java 实际的 raw 字节：

- 如果 Java 是 secret.getBytes(StandardCharsets.UTF_8)，且 secret 是去掉横杠的 32 个 ASCII 字符 UUID，那么选 256 bit + UTF-8 Key；将 secret 原样填入原始 Key。
- 如果 Java 先把 Hex 字符串解码成原始字节，就选 Hex Key，并按解码后 16/24/32 字节选择 AES-128/192/256。带横杠的 UUID 通常是 36 个 ASCII 字节，不能直接作为 AES-256 密钥。

加密输入 UTF-8 明文，输出 Base64；解密粘贴 Java 返回的 Base64，输出 UTF-8 明文。默认 PKCS7 对应 Java 的 PKCS5Padding；也支持 NoPadding（数据必须 16 字节对齐）。ECB 加密使用分组操作，较大输入会耗费更多时间，可主动停止。

**安全边界：** ECB 不使用 IV，但这是因为它是一种存在明显弱点的旧模式，并非优势。相同明文块产生相同密文块；也不会验证密文是否遭到篡改。仅作旧系统兼容，不要用来设计新加密协议。新系统推荐 AES-GCM。


## 全工具多标签工作台与历史

- 点击 + 新建独立标签，双击标签名称或打开右键菜单重命名。标签支持拖动排序、复制完整标签、关闭其他/右侧标签及恢复最近关闭的标签（不设数量配额）。
- 超过 8 个标签时可通过快速切换下拉框选择任意标签，选中标签自动滚动到可见区域。\n- 桌面快捷键 Ctrl/Cmd+T 新建，Ctrl/Cmd+W 关闭当前工具标签，Ctrl/Cmd+Shift+T 恢复关闭；Ctrl/Cmd+Alt+左/右切换。切换标签与工具不终止其他工具标签的独立处理任务；关闭标签会取消该标签正在进行的任务。
- 内置 Java AES-256 ECB、Java AES-128 ECB、Java CBC 与 AES-256 GCM 模板，自定义模板完整保存全部参数（包括 Key、IV、AAD 和前缀）；不保存输入或结果，模板数量不设配额。每次执行 GCM 加密仍应使用新 IV。
- 每个标签有独立密文前缀输入框。假设前缀为 {AES}，加密先生成 Base64/Hex/JSON 密文，再原样拼接 {AES}；解密仅在开头完全匹配时移除一次。匹配区分大小写、保留空格、不是正则。配置了前缀却不匹配会拒绝解密；留空与旧版行为完全一致。前缀不属于 AES 明文/IV/AAD，也不受 GCM Tag 认证。
- 所有参数及历史自动完整保存，不再设置保存范围或字段开关。
- 新桌面存档采用 AES-256-GCM 和应用目录中的随机 256 位密钥，无须配置系统凭据库或输入口令。本地密钥和存档都在用户目录内，不用于抵抗已控制本机的程序；旧版系统凭据加密存档保留原有保护。浏览器预览使用 IndexedDB 中的非导出 CryptoKey。未成功读取的存档不会自动覆盖。
- 修改后约 500ms 自动保存；隐藏主窗口或正常退出会尝试刷新存档。突然断电或进程被杀可能丢失未写入的修改。保存失败时会取消正常退出并提供重试或主动放弃本次修改退出的入口。不设固定会话容量上限；保存失败时提示错误并保留之前成功写入的快照。系统管理员或已控制本机的程序仍可能访问会话。
- 清除全部工作台会清除当前标签、历史、模板及本地存档，移除相应本地密钥或旧版系统凭据。复制、导出数据与外部备份由用户自行管理。

- 右侧历史栏保留运行与关闭快照，可收起、独立滚动，按工具/类型/标签名筛选；恢复至新标签后右栏仍保持打开。逐条删除或按时间清理仅在用户操作时发生，打开的标签不受影响。
- 旧版 AES 工作台 v1/v2 存档兼容迁移；旧保存策略已经舍弃的字段无法恢复。

## 国际手机号校验

默认中国 +86，区号列表显示国旗，支持按中文、英文、ISO 代码、国际区号搜索。支持本地号码和自带 + 国际区号的号码，每行一个，不设批量条数配额；结果含有效性、长度可能性、类型、E.164、国际/国内格式等。仅依照离线号码规划判断，不保证号码实际开通或归属于某人。

## SVGA 动画预览

选择或拖入本地 .svga 文件，显示画布、格式版本、宽高、帧率、帧数、时长、图层与文件大小。支持 SVGA 1.x ZIP 和 2.x Zlib、透明棋盘格/白色/深色背景、暂停继续、停止、上一帧/下一帧、滑动定位与循环。仅支持嵌入的图片，不加载外部 URL，不支持音频；解压数据上限 32 MiB，图片与动画尺寸有安全边界。开启完整加密保存并勾选输入内容才会跨重启恢复文件字节。

### 资源使用原则（0.6.2）

用户自行决定标签、历史、模板及普通文件数量与容量。处理任务不设置固定运行时限，必要时点击停止。会话当前仍采用整份快照原子替换，超大存档会增加内存及写入开销；并非无限内存或磁盘。SVGA 解压/画布、YAML 别名展开、CSV 结构扩张、JSON 嵌套和浏览器 ZIP 格式等专用边界仍有保护，不属于会话容量配额。AES 密钥长度、填充、权限校验等正确性约束不变。
